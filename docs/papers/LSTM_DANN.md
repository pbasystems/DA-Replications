# What is LSTM DANN
LSTM-DANN is a implementation LSTM feature extractor with domain adversarial neural network (DANN) for the RUL prediction with domain adaptation. The model is based on the paper "Remaining Useful Lifetime Prediction via Deep Domain Adaptation" de Oliveira da Costa et al. (2019) targeting C-MAPSS turbofan engines

# What Missing
- The original paper uses a 90/10 split for training and cross-validation (used for early stopping), but the code uses 100/0 since hyperparameter tuning/early stopping is not the focus of this implementation. The hyperparameters are set to the values reported in the paper (Table 3) instead of being searched.
- The paper performs a grid search over Table 2's hyperparameter space and selects the combination with the lowest source RMSE per source-target pair. The code does not search — it hardcodes one manually-chosen configuration (matching Table 3's row for the pair being run) directly in `main.py`/`run_experiment.py`.
- The paper reports results averaged over 10 trials (mean ± std) per source-target pair. `main.py` runs a single trial; `run_experiment.py` implements the 10-trial averaging, but the two scripts aren't unified — `main.py` should eventually either be replaced by or delegate to the `run_experiment.py` path.
- Early stopping is not implemented. The paper's early stopping criterion is based on the source RMSE, but the code does not implement this. Instead, it trains for a fixed number of epochs (200) and saves the last checkpoint.

# Assumptions
- The paper states all activation functions are ReLU, and in their Keras implementation this means `LSTM(units, activation='relu')`, which replaces the internal `tanh` used in the cell's candidate/output equations. PyTorch's `nn.LSTM` has no constructor option for this — internally it always uses `sigmoid` for the three gates (forget/input/output) and `tanh` for the candidate cell-state and hidden-state output (Eq. 1–6 in the paper), with no way to swap `tanh` for ReLU. The implementation approximates the paper's intent with a standalone `nn.ReLU()` applied *after* the LSTM's (still tanh-based) output, inside `FeatureExtractor`, rather than inside the cell itself. This is a deliberate simplification, not an exact reproduction of Eq. 4/6 with ReLU substituted in.
- The 90/10 splitting of the training and cross-validation data is not implemented. Since the paper doesn't specify the exact method (engine-level splitting or random window-level splitting), and since window-level splitting would leak near-duplicate overlapping windows between train and CV (consecutive windows share `T_w - 1` timesteps), an engine-level split would be the methodologically sound choice if/when this is implemented.
- The paper says normalisation is performed "for each dataset individually," using "the vector of **all** inputs of the j-th feature" — read as the whole FD00x dataset (train + test combined), not just the training split, since the paper's own motivation for this normalisation is to preserve/maximise the genuine distribution shift between domains, not to avoid leakage. `run_experiment.py` follows this reading: it fits feature stats over train+test combined per domain (`compute_dataset_feature_stats`) and shares those same stats across that domain's train and test splits. **`main.py` does not** — it still fits `CMAPSSDataset`'s stats from the training split only and reuses them for test, which is the more conventional leakage-avoidant choice but diverges from the paper's stated intent. This inconsistency between the two entrypoints should be reconciled.
- The paper's evaluation protocol scores exactly one prediction per test engine — the model's last available window, compared against that engine's single true RUL from `RUL_FD00x.txt` (Table 1's test-engine counts match `RUL_FD00x.txt`'s row counts exactly, e.g. 259 for FD002). Both `main.py` and `run_experiment.py` implement this via `last_window_per_engine`, subsetting the windowed test dataset down to one sample per engine before scoring — evaluating over every sliding window instead (as an earlier version of this code did) inflates both RMSE and the Eq. 16 score substantially, since the exponential scoring term sums over ~100x more samples than the paper's protocol.
- `Regressor`/`Classifier` now accept a configurable `hidden_size`, but `LSTM_DANN.__init__` doesn't forward a corresponding parameter to either — both are pinned to the class default of `32` regardless of which source-target pair is being run. This happens to match Table 3's FD001→FD002 row, but not pairs that need a different width or 2 hidden layers.
